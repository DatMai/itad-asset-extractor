# Rules first, model last, human confirms

Build the extractor as a deterministic pipeline that runs in the browser and hands only its leftovers to the user and, optionally, an LLM. Read files with **SheetJS 0.20.3 installed from the SheetJS CDN tarball**: npm's `xlsx` is frozen at 0.18.5 inside two High-severity advisory ranges, and exceljs carries four 2026 CVEs with no upstream fix ([GHSA-4r6h-8v6p-xvw6](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6), [GHSA-5pgg-2g8v-p4x9](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9), [CVE-2026-78207](https://www.cve.org/CVERecord?id=CVE-2026-78207)). Find the header by scoring the top rows, never by assuming row 1. Identify columns with **an alias table, then strict fuzzy matching, then per-field value checks**, combined into one score, the layered design that schema-matching research and commercial importers both converge on ([COMA](https://pubs.dbs.uni-leipzig.de/se/node/301), [CSVBox](https://csvbox.io/resources/ai-column-mapping)). Parse configuration strings with **hand-written regex and dictionary rules**, because no maintained library handles whole hardware strings ([cpumodel](https://pypi.org/project/cpumodel/0.0.2)). An LLM with structured output guarantees schema-valid JSON, not correct answers ([Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)), so it takes the last slot: the few columns or rows the rules leave open. For the interface, copy the importers' shared **upload → header → map → review** flow and label doubt in words, not percentages ([Dromo settings](https://developer.dromo.io/settings/), [Google PAIR](https://pair.withgoogle.com/chapter/explainability-trust/)). Two cautions: SheetJS has shipped no release since July 2024 ([SheetJS tags](https://git.sheetjs.com/api/v1/repos/sheetjs/sheetjs/tags)), and the scoring heuristics below are syntheses with no published accuracy on asset sheets, so tune them on real files.

For arbitrary spreadsheets, format breadth and one code path outweigh the saving.

**Parse in the browser.** Vercel Functions reject bodies over **4.5 MB** with a 413, and Server Actions accept **1 MB** by default ([Vercel limits](https://vercel.com/docs/functions/limitations), [Next.js serverActions](https://nextjs.org/docs/app/api-reference/config/next-config-js/serverActions)). With no upload, neither limit applies, the file never leaves the device, and a parser flaw cannot reach the server. Load the parser with `await import("xlsx")` inside the file handler so it downloads only when a file is chosen. SheetJS warns that parsing large workbooks on the main thread can freeze the page and documents Web Workers as the fix ([SheetJS worker demo](https://docs.sheetjs.com/docs/demos/bigdata/worker)). A Worker also confines a zip bomb or regex blow-up to a killable thread; no timings for multi-megabyte files were found, so measure before skipping it.

**CSV needs no second parser if the app controls decoding and coercion.** CSV bytes passed as an array or buffer without a UTF-8 BOM are read as Latin-1 unless `codepage: 65001` is set, and without `raw: true` numeric-looking text becomes numbers and date-looking text becomes date codes ([0.20.3 source](https://cdn.sheetjs.com/xlsx-0.20.3/package/xlsx.mjs), [parse options](https://docs.sheetjs.com/docs/api/parse-options)). So decode with `TextDecoder` (UTF-8, falling back to windows-1252) and call `XLSX.read(text, { type: "string", raw: true })`, which keeps leading zeros, long serials and ambiguous dates such as 12/03/2021 as text. Delimiter detection samples only the first 1,024 characters, where title rows sit ([parse options](https://docs.sheetjs.com/docs/api/parse-options)), so offer an override through the `FS` option and treat a one-column result as a failed detection. Papa Parse would add a reported delimiter and per-row error codes ([Papa Parse docs](https://www.papaparse.com/docs)), a convenience only. These behaviours were read from docs and source, not test runs, so cover them with fixtures, including a CSV whose first cell is `ID`, which file-type sniffing can take for SYLK ([parse options](https://docs.sheetjs.com/docs/api/parse-options)).

**Four workbook traps need explicit handling.** Dates are stored as numbers, and with `cellDates: true` the Date objects from `sheet_to_json` are built in local time unless `UTC: true` is passed ([dates](https://docs.sheetjs.com/docs/csf/features/dates), [array utilities](https://docs.sheetjs.com/docs/api/utilities/array)), so serialising with `toISOString()` east of UTC lands on the previous day. The zone-free route keeps the numeric code, identifies date cells with `XLSX.SSF.is_date` on formats retained by `cellNF: true`, converts with `XLSX.SSF.parse_date_code`, and checks `wb.Workbook.WBProps.date1904` ([dates](https://docs.sheetjs.com/docs/csf/features/dates), [cell objects](https://docs.sheetjs.com/docs/csf/cell)). Excel itself strips leading zeros, shows long numbers in scientific notation and truncates beyond 15 digits ([Microsoft Support](https://support.microsoft.com/en-us/office/keeping-leading-zeros-and-large-numbers-1bf7b935-36e1-4985-842f-5dfa51f85fe7)); read serials and asset tags as `String(v)` from the raw value, never from formatted text ([cell objects](https://docs.sheetjs.com/docs/csf/cell)), and accept that digits Excel already dropped from numeric cells are gone. Only the top-left cell of a merge holds the value, with ranges in `ws["!merges"]` ([merges](https://docs.sheetjs.com/docs/csf/features/merges)); forward-fill before header detection. Hidden sheets and rows are read by default ([visibility](https://docs.sheetjs.com/docs/csf/features/visibility), [array utilities](https://docs.sheetjs.com/docs/api/utilities/array)), so decide deliberately whether to ingest them. Date handling changed in 0.20.0 ([dates](https://docs.sheetjs.com/docs/csf/features/dates)), so advice written for npm's 0.18.5 does not carry over.

### Score the top 30 rows for a header instead of trusting row 1

**Recommendation: score each of the first 30 rows, take the best, and ask the user to confirm when the margin is thin.** Read raw rows with `sheet_to_json(ws, { header: 1 })`, which returns arrays and keeps blank rows ([array utilities](https://docs.sheetjs.com/docs/api/utilities/array)). Score each row on fill ratio against the sheet's modal width, share of text cells, uniqueness, hits against the asset-field alias list (serial, model, manufacturer, asset tag) and contrast with the next three to five non-empty rows. Penalise single-cell rows, and test whether merging the row above improves uniqueness, which catches two-row headers. This composite is assembled from the published heuristics below and is untested.

Weight alias hits and fill ratio above type contrast. Commercial importers use the simplest signals: Flatfile's default scans the first 10 rows and takes the fullest, and OneSchema skips its header step when detected names match the template ([Flatfile xlsx extractor](https://flatfile.com/plugins/plugin-xlsx-extractor/), [OneSchema docs](https://docs.oneschema.co/docs/2-select-header-row)). Type contrast, used by Python's `csv.Sniffer` and DuckDB, breaks on asset lists: DuckDB states it cannot detect a header when every column is text ([Python csv docs](https://docs.python.org/3/library/csv.html#csv.Sniffer.has_header), [DuckDB](https://duckdb.org/docs/stable/data/csv/auto_detection.html)). Pytheas shows what richer rules buy: it finds the first data line, scans upward for a row of unique, non-empty values, and reports **95.9% precision and 95.7% recall** on 2,000 annotated CSVs ([Pytheas paper](https://www.vldb.org/pvldb/vol13/p2075-christodoulakis.pdf)). A small TypeScript library, table-header-detective, scores similar signals but was not vetted ([GitHub](https://github.com/lyleunderwood/table-header-detective)).

## Aliases, strict fuzzy scores and value checks outvote any single matcher

**Recommendation: score every column-field pair with three matchers (alias or exact hit, strict fuzzy name similarity, per-field value validator), auto-accept only a top score that clears both a threshold and the runner-up, send the rest to the mapping screen, and call an LLM only for columns still unresolved.**

| --- | --- | --- | --- | --- |

| Fuzzy string similarity | Absorbs typos (Levenshtein), short-string variants (Jaro-Winkler) and superset headers (token-set) | Names are abbreviations or synonyms (S/N, Mem), which share few characters with the target. Look-alikes collide: token-set scoring gives a perfect score whenever one header's words are all contained in the other. Fuse.js's default threshold of 0.6 is loose for headers, and npm `string-similarity` is archived | Second pass with a strict cut-off; a vendor guide starts at 0.87, to be tuned | [CSVBox](https://csvbox.io/resources/ai-column-mapping), [RapidFuzz](https://rapidfuzz.github.io/RapidFuzz/Usage/fuzz.html), [Fuse.js](https://www.fusejs.io/fuzzy-search.html), [string-similarity](https://github.com/aceakash/string-similarity) |

The literature and the vendors agree. In Rahm and Bernstein's taxonomy this design is a composite matcher that mixes schema-level evidence (names) with instance-level evidence (values) ([survey](https://dbs.uni-leipzig.de/research/publications/a-survey-of-approaches-to-automatic-schema-matching), [course slides](https://cs.uwaterloo.ca/~tozsu/courses/cs856/F05/Presentations/Week7/CS856-SchemaMatchingSurvey-Slides.pdf)). COMA found combined matchers superior and reuse of earlier match results highly valuable ([COMA](https://pubs.dbs.uni-leipzig.de/se/node/301)). Valentine's 2021 benchmark concluded that no method wins everywhere, while a roughly 70-line Jaccard-Levenshtein baseline held its own ([Valentine](https://ar5iv.labs.arxiv.org/html/2010.07386)). Commercial importers ship the same layers behind a review screen. Flatfile's support article describes exact, then historical, then fuzzy matching, and its automap plugin proceeds unattended only when every field matches above 90% ([Flatfile support](https://support.flatfile.com/en/articles/7873666-matching), [Flatfile automap](https://flatfile.com/docs/plugins/automap)). OneSchema adds alternate column names, mapping history and AI suggestions ([names](https://docs.oneschema.co/changelog/alternative-column-name-mappings), [history](https://docs.oneschema.co/changelog/historical-column-matching-intelligence), [AI](https://docs.oneschema.co/changelog/ai-suggested-mappings-and-1-click-mode-are-now-public)). Dromo matches on header labels and data samples ([Dromo](https://dromo.io/blog/improving-data-import-accuracy-with-dromos-ai-powered-column-matching)). CSVBox cascades exact, normalised, fuzzy and semantic matching, auto-applies high confidence, flags medium and leaves low unmapped ([CSVBox](https://csvbox.io/resources/ai-column-mapping)). None publishes an algorithm or a benchmark, so every threshold is a starting point.

For the fallback, Claude's structured outputs work on every model with no beta header: pass a JSON schema in `output_config.format`, or in TypeScript wrap a Zod schema in `zodOutputFormat()` and call `client.messages.parse()` ([Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)). Make the target an enum that includes `unmapped`, because the model must be allowed to abstain ([CSVBox](https://csvbox.io/resources/ai-column-mapping)). The schema language has no `minimum` or `maximum` and does not guarantee enum capitalisation, so range-check confidence and compare enum values case-insensitively ([Anthropic structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs)). Do not use a forced tool call to get JSON: the newest models, including Sonnet 5.5 and Opus 5.5, reject forced `tool_choice` with a 400 ([Anthropic tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)). Price is not the constraint. Headers plus five sample rows, about 3,000 input and 500 output tokens before thinking tokens, cost roughly **$0.0006 per file on Haiku 5.5** ($0.10/$0.50 per million tokens), $0.011 on Sonnet 5.5 ($2/$10) and $0.022 on Opus 5.5 ($4/$20) ([Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)). Latency, privacy and run-to-run variation are the real costs, so mask serial numbers in the samples, cache results by header signature, and keep the heuristic result when the call fails. One study found names-only LLM matching workable but sensitive to too little or too much context, and complementary to string similarity ([Parciak et al.](https://arxiv.org/abs/2407.11852v1)).

## Hand-written rules parse spec strings; keywords, not magnitude, split RAM from storage

**Recommendation: split the string on its delimiters, recognise each component with its own regex or dictionary, keep the original text beside every parsed value, and send strings that do not parse cleanly to review, or to an LLM only with the user's consent. Adopt no library, and do not make the LLM the primary parser.**

No maintained library for whole configuration strings was found. The nearest are small Python CPU-name helpers, `cpumodel` 0.0.2 and Ultralytics' regexes for Intel i-series and Ryzen ([PyPI](https://pypi.org/project/cpumodel/0.0.2), [Ultralytics](https://docs.ultralytics.com/reference/utils/cpu)), useful only as pattern references. LLMs are the strongest general extractor: GPT-4 reached **91% F1** on product attribute-value extraction, about 10 points above trained taggers, which need large labelled sets and generalise poorly to unseen values ([Brinkmann et al. 2024](https://arxiv.org/abs/2403.02130), [Brinkmann et al. 2023](https://arxiv.org/abs/2310.12537v2)). That makes an LLM the right rescue for phrasings the rules miss, not the primary parser: it would send serial-bearing rows off the device, add latency, make results unrepeatable in tests, and still need the same review screen. No head-to-head comparison of regex, NER and LLM on hardware strings was found, so this ordering is engineering judgement.

For `HP EliteBook 850 G7 - i7-10610U / 16GB / 512GB SSD / 15.6in`, split on the spaced hyphen, slashes, commas and parentheses: text before the first recognised spec is manufacturer plus model, `i7-10610U` matches a CPU pattern, and `15.6in` is the screen. Bare capacities are the hard part; even production product search finds `4g` ambiguous between a network standard and 4 GB of RAM ([Amazon Science](https://cdn.amazon.science/a1/97/116ffa7f44e28bcc4bcdfccaceee/building-natural-language-interface-for-product-search.pdf)). Resolve them in this order, most reliable first: an adjacent keyword (RAM, DDR versus SSD, HDD, NVMe); unit and shape, since TB, decimals such as 3.84TB and count prefixes such as `6x` mean storage; position, following the common CPU / RAM / storage order; and magnitude last, because it fails on servers with 512 GB of RAM and on devices with 32 to 64 GB of eMMC. In the example, `512GB SSD` is storage by keyword and `16GB` is RAM by position, which deserves lower confidence. Keep an unrecognised-CPU path for new families such as Core Ultra and Apple M. These rules are untested and no open dataset of hardware strings was found, so build fixtures first.

**Normalise storage in decimal and RAM in binary.** Drive makers define 1 GB as 1,000,000,000 bytes, which is why Windows shows a 500 GB drive as 465 GB ([Seagate](https://www.seagate.com/support/kb/why-does-my-hard-drive-report-less-capacity-than-indicated-on-the-drives-label-172191en/)). JEDEC defines memory prefixes as powers of 1,024 ([JEDEC via Wikipedia](https://en.wikipedia.org/wiki/JEDEC_memory_standards)), a split NIST also documents ([NIST](https://physics.nist.gov/cuu/Units/binary.html)). So **3.84 TB is 3,840 GB of storage and 16,384 MB is 16 GB of RAM**, and cells reading 465, 476 or 931 GB are binary views of 500, 512 and 1,000 GB drives.

## Importers pre-fill every step and show doubt in words, not percentages

**Recommendation: build upload → header row → map columns → review and fix, fold header confirmation into the mapping screen, skip any step the system resolves confidently, and express uncertainty as two or three named levels with a reason.**

OneSchema, Flatfile, Dromo, CSVBox and the open-source react-spreadsheet-import share this spine ([OneSchema](https://docs.oneschema.co/docs/4-review-finalize), [Flatfile](https://support.flatfile.com/articles/7763163677-importing-data-with-flatfile-overview), [Dromo](https://developer.dromo.io/settings/), [CSVBox](https://help.csvbox.io/llms-full.txt), [react-spreadsheet-import](https://github.com/UgnisSoftware/react-spreadsheet-import)). Steps vanish when unnecessary: Dromo skips matching when every header matches exactly, and CSVBox can skip mapping on an exact match and verification when error-free ([Dromo changelog](https://developer.dromo.io/changelog.md), [CSVBox](https://help.csvbox.io/llms-full.txt)). For the **header row**, pre-select a candidate, let the user change it and discard the rows above; CSVBox adds a no-header option ([Dromo settings](https://developer.dromo.io/settings/), [CSVBox](https://help.csvbox.io/llms-full.txt)). The **mapping screen** shows one row per source column with a pre-filled target dropdown and a data preview, and in Flatfile a blank target signals that input is needed ([Flatfile](https://support.flatfile.com/articles/7763163677-importing-data-with-flatfile-overview)). Offer an ignore control ([CSVBox](https://help.csvbox.io/llms-full.txt)). react-spreadsheet-import's UI strings show that assigning a field twice un-assigns the earlier column with a notice, and that unmatched required fields are listed in a confirmation before continuing ([RSI strings](https://raw.githubusercontent.com/UgnisSoftware/react-spreadsheet-import/master/src/translationsRSIProps.ts)). Dromo lets several columns feed one field ([Dromo settings](https://developer.dromo.io/settings/)), and published guidance asks importers to show how each column was matched ([Smashing Magazine](https://www.smashingmagazine.com/2020/12/designing-attractive-usable-data-importer-app/)).

The **review screen** is an editable grid with cell-level severity (error, warning, information), messages on hover, an issues-only filter and bulk fixes ([Dromo changelog](https://developer.dromo.io/changelog.md), [CSVBox](https://help.csvbox.io/llms-full.txt), [react-spreadsheet-import](https://github.com/UgnisSoftware/react-spreadsheet-import)). Flatfile underlines auto-transformed values and shows the original on hover ([Flatfile](https://support.flatfile.com/articles/7763163677-importing-data-with-flatfile-overview)), the right treatment for normalised units. State the submit-with-errors policy; Dromo offers block, drop invalid rows after confirmation, or include after a warning ([Dromo settings](https://developer.dromo.io/settings/)). Freeze the header row and identifier column and show the active filter ([NN/g data tables](https://www.nngroup.com/articles/data-tables/)). For **failure states**, state format, required fields and row cap before upload ([Smashing Magazine](https://www.smashingmagazine.com/2020/12/designing-attractive-usable-data-importer-app/)). On failure, name the cause and the remedy and keep the user in the flow, as Flatfile does for corrupted files and CSVBox for password-protected ones ([Flatfile](https://support.flatfile.com/articles/7763163677-importing-data-with-flatfile-overview), [CSVBox](https://help.csvbox.io/llms-full.txt)); put the message at the source, use cues beyond colour and preserve input ([NN/g error messages](https://www.nngroup.com/articles/error-message-guidelines/)). Past a row cap, Dromo warns and drops the extra rows, and CSVBox shows the truncated count with an option to continue ([Dromo settings](https://developer.dromo.io/settings/), [CSVBox](https://help.csvbox.io/llms-full.txt)). No vendor documents empty-file or no-table-found messages, so write those from first principles.

On **confidence**, Google's PAIR guidebook says to show it only where it changes a decision, prefers named categories with defined cut-offs and an implied action, and warns that percentages assume probability literacy and invite over-trust ([Google PAIR](https://pair.withgoogle.com/chapter/explainability-trust/)). Azure Document Intelligence uses field confidence to split auto-accept from human review and notes that a confident cell can sit in a doubtful row ([Azure Document Intelligence](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/concept/accuracy-confidence)). Importers already show doubt categorically, through warning tiers and auto-changed markers, and none of the pages read documents a numeric match score ([Flatfile](https://support.flatfile.com/articles/7763163677-importing-data-with-flatfile-overview), [Dromo changelog](https://developer.dromo.io/changelog.md)). So add low confidence as a non-blocking tier in the same issues filter, with a row flag and a cell-level reason, and keep any numeric score secondary.

## Conclusion

The four answers are one architecture seen from four sides: every stage is a cheap deterministic layer that emits a value, a confidence level and a reason, and the review screen resolves the leftovers. That reframes the LLM question. At a few cents per file at most, price is not what keeps the model last ([Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)); repeatability, privacy and latency are. If those relax, the model can move earlier without changing the design, because the abstain option and the human check stay.

What remains unknown is accuracy. No published benchmark covers header detection, header matching or spec parsing on asset sheets, vendor documentation discloses no figures, and several literature and vendor findings were read from summaries, not full texts. The fixture set of real, messy files with expected outputs is therefore the project's most valuable asset: tune every threshold against it, and turn every user correction into a new alias, the reuse COMA found most valuable ([COMA](https://pubs.dbs.uni-leipzig.de/se/node/301)). Finally, isolate SheetJS behind one reader function. Its 28-month release gap is the design's one dependency risk ([SheetJS tags](https://git.sheetjs.com/api/v1/repos/sheetjs/sheetjs/tags)), and a narrow interface keeps read-excel-file plus Papa Parse available as a retreat.
