# Plan

Short on purpose. Requirements are in `spec.md`; reasons are in `research.md` and
`.local-map/DECISIONS.md`. Status is kept in `.agent/HANDOFF.md`.

## Shape

```
file (browser)
  └─ readWorkbook        bytes -> sheets of plain text cells      (the only code that knows SheetJS)
       └─ detectHeader   which row holds the column names, if any
            └─ mapColumns     column -> field | combined | ignore, with confidence and reason
                 └─ extractAssets  row -> asset
                      ├─ normalise      one cell -> one clean value   (RAM, storage, screen, type, CPU, date)
                      └─ parseFreeText  one combined cell -> several values
                           └─ exportAssets  assets -> CSV / JSON, checked by a Zod schema

UI (one page):  upload  →  mapping panel (fix)  →  results table (review, edit)  →  export
optional:       POST /api/suggest-mapping  →  Claude, for columns the rules left unsure
```

Everything under `src/lib/extraction` is pure functions on plain data: the same code runs in the
browser and in Vitest. The UI keeps state (sheets, chosen header rows, mappings, manual edits) and
re-runs `extractAssets` whenever a mapping changes.

## Steps

Each step is test-first and ends with `pnpm typecheck && pnpm lint && pnpm test` passing.

| # | Step | Done when |
| --- | --- | --- |
| 1 | Normalisers | AC5 table passes |
| 2 | Free-text parser | All 16 descriptions of sample 2 and the cells of `Sheet1 (2)` parse exactly |
| 3 | Column mapper | All columns of both samples map with confidence ≥ 0.9; typos, abbreviations, Vietnamese, headerless |
| 4 | Header detection | Row 4 and row 3 of sample 1; row 1 of sample 2; no header; unknown names |
| 5 | Workbook reader | xlsx, xls, csv (`,` `;` tab), BOM, date cells, limits, clear errors |
| 6 | Row assembly | AC1–AC4 on the real sample files: 15 + 4 assets, TOTAL skipped, 14 computers + 2 non-computers |
| 7 | Self-made fixtures | AC7: four files unlike the samples, generated by `pnpm fixtures` |
| 8 | Export | AC8: CSV and JSON validated by Zod; formula injection neutralised |
| 9 | UI | Upload, mapping panel, results with confidence and inline edit, tabs, export, error states (AC6, AC12) |
| 10 | LLM suggestion | Opt-in route; heuristics stand when it fails; prompt in `src/lib/llm/prompt.ts` |
| 11 | README and demo script | AC10, AC11 |
| 12 | Review as the client would | `reviewer` checklist in `.claude/agents/reviewer.md`; fix findings |

## Order of cuts if time runs out

Drop from the bottom: step 10 (LLM), then inline editing in step 9, then the extra fixture formats
in step 7. Steps 1–6 and the mapping panel are the product.

## Not planned

Persistence, accounts, dashboard, server-side parsing, Playwright, per-cell LLM parsing, several
tables in one sheet, transposed tables. See "Known limitations" in the README.
